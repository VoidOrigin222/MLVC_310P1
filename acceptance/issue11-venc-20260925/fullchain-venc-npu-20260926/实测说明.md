# 编解码全链路与 NPU 使用率实测（2026-09-26）

## 本轮处理

优化的是解码端 FP16 YUV444→NV12 转换：在 `custom_ops/mlvc_prior_ops/op_kernel/mlvc_fp16_yuv444_to_nv12.cpp`
中，将 Y 平面的 FP16 转 FP32、缩放、clamp、RINT 改为 AscendC 向量指令；UV 路径向量化两行 FP32
累加，最后保留交错写入。310P1 DVPP VPC 不支持直接接收当前 FP16 输入，因此没有切换到 VPC。
VENC 通道跨帧复用未启用，板端验证时第二帧提交返回 `HI_ERR_VENC_ILLEGAL_PARAM`。

## 全链路

`编码端 Ascend 310P1 → RTP/UDP 39220 → 解码端 Ascend 310P1 → DVPP VENC/RTSP → PC MediaMTX/FFmpeg`

- 同一 537 帧编码输入；编码端和解码端均为 Ascend 310P1/CANN 9.1。
- 解码端通过 `MLVC_PRIOR_OPAPI_LIB` 与 `ASCEND_CUSTOM_OPP_PATH` 临时加载向量化实验包；未覆盖系统原算子包。
- 编码：**33.5402 FPS**，537/537 帧，`encode=ok`。
- 解码：**29.8693 FPS**，537/537 帧，`decode=ok`。
- 解码端 RTSP 发布 537 帧，`forward_dropped_frames=0`；PC FFmpeg 收到 484 帧，连接发生在流开始后，少于发布计数不代表解码端丢帧。

## NPU 采样

解码板运行期间共采到 18 个 `npu-smi info` 快照；每次 SSH 采样间隔约 1.3–1.5 秒：

| 指标 | 结果 |
| --- | ---: |
| AICore 平均（全部快照，含启动/结束空闲） | 56.28% |
| AICore 平均（非零活动快照） | 84.42% |
| AICore 峰值 | 90% |
| NPU 内存峰值 | 19,653 / 44,254 MB（约 44.4%） |
| 运行前 NPU 内存 | 18,463 MB |
| 运行后 NPU 内存 | 18,465 MB |

运行结束后解码进程退出，内存占用回到运行前水平附近。以上 AICore 数值是 `npu-smi` 离散快照，不能视作设备内部的精确时间积分利用率。
