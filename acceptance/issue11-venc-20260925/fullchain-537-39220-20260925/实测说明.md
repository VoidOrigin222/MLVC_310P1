# Issue 11 全链路实测（537 帧）

日期：2026-09-25

## 链路

编码端 Ascend 310P1 → RTP/UDP `39220` → 解码端 Ascend 310P1 → DVPP H.264 VENC → MediaMTX → PC FFmpeg。

输入为编码板上的 `614lab_1080p_fp16_100_loop537`，分辨率 `1920×1080`，共 537 帧。RTSP 地址为：

```text
rtsp://<MediaMTX-IP>:8554/mlvc-fullchain-537-39220-20260925
```

解码板的 RTSP 发布程序需要使用板上已存在的精简 FFmpeg：

```sh
export PATH=/path/to/ffmpeg-runtime/bin:$PATH
```

## 结果

| 环节 | 结果 |
| --- | --- |
| 编码端 | `537/537`，`encode=ok`，`33.5355 FPS` |
| RTP MLVC | 编码端与解码端 `bitstream_bytes=644207` 一致 |
| 解码端 | `537/537`，`decode=ok`，`29.7511 FPS` |
| DVPP VENC/RTSP | H.264，1920×1080，30 tbr；发布 `537` 帧 |
| 解码端丢帧 | `drop_frame_index=-1`，`forward_dropped_frames=0` |
| PC FFmpeg | 成功识别 H.264 Baseline 并收到 `486` 帧 |

PC 客户端在发布流建立后才完成 RTSP 握手，因此从正在发送的流中间开始计数，少于解码端发布的 537 帧；这不是解码端丢帧。解码端日志确认 DVPP VENC 已发布全部 537 帧，且无转发丢帧。
