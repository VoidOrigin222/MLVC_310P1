# 实时相机在线速度验收

验收日期：2026-10-02。测试源码为已部署的 `afd4a0f`，本轮只验证在线速度，
没有修改生产代码、配置默认值或原部署。测试资产位于两板
`/root/workplace/grifcc/online-validation`。

## 已确认结论

已完成的 1080p 实时相机 → DVPP 运动代理 → MLVC 编码 → 双机 RTP 3000 帧长测，
编码 **26.7962 FPS，未达到 30 FPS**，采集序号缺口 **333**。
接收解码为 26.809 FPS，编码与输出均为 3000 帧；
此前 300 帧短测编码为 27.2367 FPS、接收解码为 27.4161 FPS。
接收解码包含等待在线帧到达，不是独立解码极限。
相机单独采集 300 帧约为 29.85～29.88 FPS，接近其 advertised 30 FPS。

[文件输入长测](../motion-throughput-20261002/README.md) 的约 30.5 FPS 来自无节拍
文件输入，不作为此次相机在线测试的速度。本轮量化平移均为 0（`motion_nonzero=0`），
未验证持续显著全局平移场景；量化中位数为零不能证明物理场景静止。

## 测试条件

- 输入：V4L2 `/dev/video0`，MJPG、1920×1080、advertised 30 FPS。
- 实时采集，`camera_preload_frames=0`，未启用 RTSP 或 trace。
- QP 11、GOP 96、feature reset 32、LTR 关闭。
- DVPP 运动代理、`motion_prefetch_frames=2`、`motion_skip_loop_filter=true`。
- RTP 传到另一板解码；在 `/root/workplace/grifcc` 的独立部署运行。

## 300 帧短测结果

| 指标 | 结果 |
| --- | --- |
| 编码 / 接收解码 FPS | 27.2367 / 27.4161 |
| 编码 / 解码输出帧数 | 300 / 300 |
| 相机读取帧数 | 307 |
| V4L2 sequence gaps | 21 |
| JPEG 错误 | 0 |
| 网络 forwarding drop | 0 |
| 非零运动帧 | 0；未验证持续显著全局平移场景 |
| source-ready → output 平均 / 最大 | 129.329 / 200.689 ms |

V4L2 sequence gaps 是采集序号缺口，不能用网络 forwarding drop 为零来宣称全链路
无掉帧。source-ready 在源 tensor 准备完成后计时，**不包含相机内部队列及采集过程**；
output 终点是发送端输出/入队调用，不是接收显示，不能当作完整拍摄到显示时延。

各环节平均耗时如下；它们有不同计时边界，不能直接相加作为单帧总延迟：
JPEG 解码计时是该阶段的墙时，不是纯硬件核耗时。

| 环节 | 平均耗时 ms |
| --- | ---: |
| 相机 JPEG 解码 | 24.9242 |
| NV12 D2H | 2.59795 |
| BGR 转换 | 1.71335 |
| BGR → FP16 | 20.5851 |
| AIPP | 0 |
| 输入运动准备 | 35.7192 |
| 运动代理工作 | 26.2312 |

输入运动准备包含 external FP16 mirror 和 FP16 → NV12 转换。
这些数据说明实时采集与转换的成本已进入运行路径；本记录不据此把单一环节认定为
唯一瓶颈，也不将文件输入吞吐外推到实拍。

## 正式 3000 帧实拍长测

使用同一测量源码 `afd4a0f` 和相机条件，实际实时读取 3007 帧，编码 3000 帧。
编码 FPS 排除前 96 帧预热，测量 2904 帧；不是重复文件测试。

| 指标 | 结果 |
| --- | --- |
| 测量编码 FPS | **26.7962** |
| 三个 900 帧窗口 FPS | 26.7362 / 27.0223 / 26.3974 |
| 接收解码 FPS | 26.809，包含等待在线帧到达 |
| 编码帧统计 | 3000：I=32、P=2968 |
| 解码 / output / forward_dropped | 3000 / 3000 / 0 |
| 相机读取帧数 / V4L2 sequence gaps | 3007 / 333 |
| JPEG 错误 | 0 |
| 两端熵载荷 / 几何 / codec total | 996976 / 5936 / 1002912 字节 |
| 非零运动帧 | 0；本轮量化平移均为零，未验证持续显著全局平移场景 |
| source-ready → codec 平均 / 最大 | 97.9663 / 159.899 ms |
| source-ready → RTP enqueue 平均 / 最大 | 128.259 / 213.277 ms |
| camera queue 满等待次数 / 最大深度 | 2950 / 3 |
| tensor queue 满等待次数 / 最大深度 | 2943 / 3 |

采集序号缺口 333 表示采集环节有漏取；3000 帧全部解码只证明已编码、发送的帧完整，
不能宣称完整拍摄链路无掉帧。上述时延不包含 camera/driver 前置队列、网络和显示。
`motion_prefetch_frames=2` 只限制 arena 的三帧 lease；前置 camera queue、tensor queue
分别最多三帧，driver 缓冲另算，不能把这些队列忽略后称作总延迟两帧。

长测各环节平均耗时：
JPEG 解码同样记录阶段墙时，不是纯硬件核耗时。

| 环节 | 平均耗时 ms |
| --- | ---: |
| 相机 JPEG 解码 | 24.3559 |
| NV12 D2H | 2.46495 |
| NV12 → BGR | 1.70526 |
| BGR → FP16 | 20.2081 |
| AIPP | 0 |
| 输入运动准备 | 36.334 |
| 运动代理工作 | 26.3174 |

输入运动准备平均 36.334 ms 超过 30 FPS 的单阶段 33.33 ms 预算。相比文件输入，
该实拍路径多了每帧 12,533,760 字节的 external FP16 mirror，以及
MJPEG → NV12 → BGR → FP16 → NV12 往返。各线程工作有并行，计时不能相加。
这些是后续减少镜像拷贝和颜色往返的调查方向；本轮没有实施优化。
